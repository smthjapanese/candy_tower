# Сладкая Башня — Yandex Games проект

Гибрид Timing-Stack + Merge с направленным креном («живая» физика без тяжёлого движка),
конфетной темой и тремя источниками монетизации через Yandex SDK.

## Структура проекта

```
candy-tower/
├── index.html          — точка входа, сюда платформа подставляет /sdk.js
├── css/main.css
├── src/
│   ├── yandex-bridge.js — обёртка над Yandex SDK (реклама, сохранения, готовность)
│   └── game.js           — вся игровая логика (Phaser)
├── assets/                — пока пусто, см. "Что нужно добавить" ниже
└── README.md
```

## Как тестировать локально

Просто открой `index.html` в браузере (или подними локальный сервер, например
`python3 -m http.server` в этой папке и зайди на `localhost:8000`).

На платформе Yandex файл `/sdk.js` подставляется автоматически хостингом — локально
его нет, поэтому `yandex-bridge.js` сам подставляет тестовую заглушку с тем же
интерфейсом. Реклама в заглушке "показывается" мгновенно и сразу засчитывается —
это нормально, так и должно быть при локальном тестировании. Проверить, что это
тестовый режим, можно по надписи в консоли браузера
`[yandex-bridge] /sdk.js не найден — используется локальная заглушка`.

## Что уже подключено

**Монетизация (все три канала из плана):**
- **Rewarded-видео** — кнопка «Второй шанс» появляется один раз за забег, когда башня
  падает. Досмотрел ролик — башня выпрямляется, игра продолжается с того же места.
- **Межстраничная реклама** — показывается автоматически между забегами, но не каждый
  раз (сейчас: каждая вторая смерть, см. `INTERSTITIAL_EVERY` в `game.js`), чтобы не
  раздражать игрока слишком частыми показами.
- **Sticky-баннер** — пока не подключен, включается одной галочкой прямо в консоли
  разработчика Яндекса после публикации, кода в проекте для этого не нужно.

**Сохранения:** рекорд и накопленная валюта («конфеты») сохраняются через
`ysdk.getStorage()` — это устройство-локальное хранилище SDK, работает без авторизации
игрока. Если платформа недоступна (или это локальный тест), автоматический откат на
`localStorage`.

## Что нужно сделать перед публикацией

1. **Иконка игры** — 512×512px, PNG. Загружается прямо в консоли разработчика при
   создании карточки игры, класть в проект не нужно.
2. **Скриншоты/промо-картинки** — тоже через консоль, не в архив.
3. **Phaser сейчас грузится с CDN** (`cdnjs.cloudflare.com`). Для продакшена лучше
   скачать `phaser.min.js` и положить его в `src/vendor/`, подключив локально —
   это уберёт лишний сетевой запрос и ускорит первый показ игры (важно для
   ранжирования на площадке). У меня в этой среде нет доступа в интернет, чтобы
   скачать файл за тебя — сделай `curl` или просто скачай вручную с
   `https://cdn.jsdelivr.net/npm/phaser@3.70.0/dist/phaser.min.js` и подмени
   `<script src="...">` в `index.html` на локальный путь.
4. **Возрастной рейтинг и категория** — выставляются в консоли (для этой игры
   разумно 0+ или 6+, никакого чувствительного контента нет).
5. **Ориентация экрана** — игра рассчитана на портретную ориентацию (400×700 canvas,
   масштабируется через `Phaser.Scale.FIT`), в консоли укажи "портрет".

## Как собрать архив для загрузки

Всё содержимое папки `candy-tower/` (кроме этого README, он не обязателен, но не
мешает) нужно упаковать в .zip **так, чтобы `index.html` лежал в корне архива**,
а не во вложенной папке — иначе модерация Яндекса отклонит билд.

## Известные упрощения прототипа (можно доработать позже)

- Иконки/арт — геометрические фигуры с бликом, а не готовая графика. Можно заменить
  на настоящие спрайты, структура кода это позволяет (`drawBlock()` в `game.js`).
- Косметические скины за накопленные "конфеты" — валюта уже копится и сохраняется,
  но магазина скинов пока нет — следующий логичный шаг для повышения retention.
- Лидерборды Yandex SDK (`ysdk.leaderboards`) не подключены — хорошая точка для
  следующей итерации, повышает виральность и соревновательность.
